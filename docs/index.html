The core idea

Resolution is the wrong unit

A flat 4K video puts 3840 pixels across the screen. A 360° video spreads those same pixels around the viewer's entire head — and the headset shows only about 96° at a time. The viewer sees roughly a quarter of the frame, stretched across the whole display.

So the meaningful unit is pixels per degree. And by that measure a 4K 360° stream is supplying about half the detail the panel can show.

The headset shows 1832 pixels per eye across ~96°. A 4K 360° frame can only supply 1024 of them — the display is asked to show detail that was never encoded.

Counterintuitive

More pixels can make quality worse

In a seven-way A/B comparison on the headset, an 8K encode at 45 Mbps scored lowest of all seven. Spread across 59 megapixels, every pixel is starved. A 4608² encode at the same bitrate was indistinguishable from a 5760² one.

If something looks soft, the lever is bitrate or codec — not resolution. Raising resolution inside a fixed bandwidth budget actively hurts.

What it caught

Two defects, same symptom

Both titles looked "fuzzy". The causes were unrelated — which is the argument for auditing a library by measurement rather than fixing titles one complaint at a time.

Over the decoder's bitrate limit

An 8K master encoded at 251 Mbps against the headset's 220 Mbps H.264 ceiling, with a nonstandard profile level. The decoder can't keep up, so playback silently falls back to a degraded path.

Mono video labelled as stereo

A normal mono 360° frame tagged top-bottom stereo. A player honouring that tag splits one image in half and sends the sky to one eye and the ground to the other, stretching each 2× vertically — half the resolution, plus two eyes that cannot fuse. PSNR between the halves was 7.1 dB; genuine stereo measures ~25 dB.

Using it

Three commands

brew install ffmpeg          # must include libsvtav1
./check_setup.sh             # verifies this machine can run it

./inspect_master.sh /path/to/masters/   # read-only: what are these files?
./encode_vendor.sh  /path/to/masters/   # encode the batch
./verify_final.sh   final/output.mp4    # check before uploading

The encoder auto-detects each file's projection, stereo layout and frame rate, picks the right target, restores the 360° metadata FFmpeg strips from every output, and refuses to guess when a file looks mislabelled.

Honest scope

Prior art

The individual techniques here are established. Viewport-based quality measurement is standardised in JVET's 360Lib (WS-PSNR, S-PSNR, viewport PSNR). Spatial metadata injection has existing tools. Pixels-per-degree is ordinary display engineering. AV1 for VR is widely documented.

What this adds is the integration: targets derived from measured device limits rather than published specs, format auto-detection with a geometry sanity check, metadata repair, and verification gates — in one pipeline that refuses to guess when a file looks wrong.
